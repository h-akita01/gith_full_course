# チケット予約API リクエストボディのテスト条件（同値分割・境界値分析）

## 前提

### ステータスコード

| ステータスコード | 意味 |
|:---:|---|
| 201 | 正しい入力（正常系）。予約が作成される |
| 400 | 入力バリデーション違反（異常系）。必須・文字種・桁数・形式・型のエラー |
| 409 | ビジネスルール違反。予約代表者の年齢が18歳未満 |

- 入力バリデーションはビジネスルールより先に判定されるものとします。たとえば代表者の年齢 `-18` は18歳未満ですが、半角数字ではないため 409 ではなく 400 になります。
- 1つの項目を検証するときは、ほかの項目に正しい値を入れます（例：代表者 `ヤマダ / タロウ / 30 / M / 03 / 1234 / 5678 / taro@example.com`、搭乗者1件）。
- 「未指定」は、項目のキーを省略した場合と値を `null` にした場合を指します。

### 仕様の確認結果として反映した内容

| 項目 | 反映した内容 |
|---|---|
| カタカナとして認める文字 | 長音「ー」、「ヴ」、小書き文字「ァ」などを使える（正常系として追加） |
| 全角スペース | カタカナではない文字として扱う。全角スペースだけの値、全角スペースを含む値を 400 とした |
| 中黒「・」 | 記号として扱う。「・」を含む値を 400 とした |
| メールアドレスの下限 | 仕様どおり「1〜256文字」で進める。1文字は境界値としてテストするが、形式を満たせないため結果は 400 |
| 年齢の先頭ゼロ | UIで取り除いてから送られるため、API のテスト対象外とした（`018` のケースは作らない） |
| 年齢の型 | 数値（number）として送られる。文字列の `"18"` は型違いとして 400 とした |
