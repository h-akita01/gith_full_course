### 0.1 工程の省略について
- **Phase 6（組み合わせテスト）は作成していない。** 2026-10-05 に人間から「時間がないから7に進んで」と指示があったためである。このため、テストケースに COMB-xxx は紐付いていない。
- 参考：組み合わせの因子になりうるのは搭乗クラス（2値）と時期区分（3値）の2つだけである（区間・割引額は値が1つに固定。HD-001, HD-002）。この2因子の全組み合わせ（6通り）は、デシジョンテーブル DT-001〜DT-006（TC-001〜TC-006）ですべて扱っている。
- Phase 5（状態遷移）は対象なし（HD-018）のため、ST-xxx・TR-xxx は紐付いていない。

### 0.2 作成方針
- テストモデル（EQ / BVA / DT）の正常クラス・境界・ルールから、テストケースを作成する。対象外のモデル（EQ-003, EQ-016, EQ-018, EQ-020, EQ-024）からはテストケースを作らない（HD-003〜HD-006, HD-011）。
- Then で確認するのは運賃だけとする（HD-017）。
- 同じ値を繰り返すシナリオは Scenario Outline にまとめ、Examples の1行を1テストケース（TC-xxx）とする。
- **1つの Scenario Outline の中で、入力と期待結果が同じになるモデルの値は1行にまとめ、該当するモデルIDをすべて記載した。** 例：BVA-003 の境界値（1月5日）と BVA-004 の境界直前（1月5日）は同じ日付なので1行にした。
- 異なる Scenario Outline の間の重複（例：TC-001 と TC-013 はどちらも「一般席・8月13日」）は、テスト技法が異なるため本工程では残し、Phase 8（重複の整理）で扱う。
- 年が期待結果に関係しない日付は、月日だけで書く（時期は月日で定義されている。SPEC-5）。2月29日は、存在する年（うるう年）を指定する（HD-007）。

## 1. Feature：運賃の算出

```gherkin
Feature: 運賃の算出
  運賃 = 基本運賃 − 運賃種別ごとの割引額（100円未満は切り上げ）
  基本運賃 = （区間の基本料金 + 搭乗クラスの加算料金）× 積算比率(%)

  Background:
    Given 区間の基本料金が 10,000円 の区間を指定している
    And 割引額が 0円 の運賃種別を指定している
```

Background の根拠：SPEC-2, SPEC-3 / BR-001, BR-003 / EQ-017, EQ-019 / HD-001, HD-002

### 4.1 自己レビューで判断した点
- 同じ Scenario Outline の中で入力と期待結果が同じ値は、1行にまとめてモデルIDを列挙した（0.2）。異なる Scenario Outline の間の重複は Phase 8 で整理する。現時点で把握している重複候補は次のとおり。
  - TC-001 と TC-013（一般席・8月13日）、TC-002 と TC-012（一般席・7月28日）、TC-003 と TC-011（一般席・5月15日）
- TC-063〜TC-069 は仮の値を使うため、運賃算出の入力からは実行できない。端数処理だけを実行する方法は仕様に書かれていない（2章の補足）。テスト実施前に確認が必要。
- 修正を要する問題は見つからなかった。
